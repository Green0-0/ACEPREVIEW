No per-instance data was available locally; every number below is derived from aggregate counts. Each pairwise comparison gives both marginals and both discordant counts, so the **full paired 2x2 table is recoverable** and the paired effect sizes below are exact. **Primary analysis (pre-registered):** NEAT best r1 vs the no-step-limit baseline, one-sided exact McNemar (H1: NEAT resolves more). Everything else is secondary/descriptive.

- AUC = 0.891 (Hanley–McNeil 95% 0.869 to 0.914).
- Point-biserial r = 0.530; Fisher-z 95% CI 0.501 to 0.558 with n = 2500, or 0.464 to 0.590 with the conservative n = 500 instances (pairs share instances, so the pooled n overstates precision).
- Mean proxy: resolved 0.703 vs unresolved 0.213 (difference 0.491).

4. **Cohen's d on the proxy with per-group SDs** (and Glass's Δ), plus an instance-clustered bootstrap CI for AUC and r_pb that respects the 5 systems sharing each instance. Section 6 derives d assuming a pooled SD.
5. **Holm/BH on the token Wilcoxon tests** is computable here, but effect sizes for them (matched-pairs rank-biserial r, Hodges–Lehmann median ratio with CI) need the per-instance token vectors.
6. Conditional (within-instance) analyses of **empty patches and agent failures** (e.g. resolve rate of the baseline on instances where NEAT's pick-merger failed, paired by instance).
7. NEAT curves corrected for minibatch difficulty at the task level (instance fixed effects) need `$ACE/runs/neat_{a,b}/evaluations.jsonl`; this is partly done in `results/graph_analysis`.

## Inconsistencies and caveats noticed in existing results

- `report.md` prints McNemar p as `0.0000`; the exact values are 9.1e-15 (NEAT r1) and 5.8e-13 (NEAT r2). the earlier experiment notes' “p < 1e-4” is true but understates them by 10 orders of magnitude.
- the earlier experiment notes' proxy AUC “0.88” is the v1 value (2000 pairs); v2 (2500 pairs incl. the no-limit baseline) gives 0.891.
- the earlier experiment notes stated both “NEAT uses 0.61× the tokens” (vs no-limit, median of per-instance ratios) and “about 1.4–1.5× the baseline's tokens” (vs the 30-step baseline, from v1). Both are right but the reference must be named each time. Ratio of medians (0.63×) and ratio of totals (0.17×) also differ a lot from 0.61× because of the no-limit baseline's heavy token tail.
- Uncached token medians differ 2.5× between the two identical 30-step baseline runs (44K vs 108K) while all-token medians agree (362K vs 368K): the cache-hit rate depended on cluster load (see INTERVENTIONS.md thrash entries). Uncached efficiency figures therefore reflect serving conditions as much as the pipeline.
- baseline_30step r1 has 2 eval `error` statuses counted as unresolved; NEAT r1/r2 have 95/93 agent failures (pick-merger) counted as unresolved. Both conventions are conservative for the respective system but should be stated.
- The NEAT block in analysis_v2 (A 13, B 19 generations) and the graph-analysis snapshot (A 11, B 13 generations) are different snapshots of still-running jobs; numbers quoted from the two sources will not match exactly.
- `spearman_generation_vs_mean` in report.json is computed on the per-batch mean task score (all genomes evaluated on that batch, including one more batch than logged generations), not on `mean_fitness_by_generation`; both are reported in Section 7.
- Proxy validity pools 5 systems × 500 instances as if independent (n = 2500); the p = 3.7e-181 is overstated.
- The val40 p = 0.025 is uncorrected for four candidates and is computed on the selection set (winner's curse); Holm-adjusted it is ≈0.10.
- The 30-step baseline comparisons were tested one-sided in the direction “30-step > no-limit”, which was not a hypothesis anyone held; quote the two-sided p.
- django__django-10097 is “resolved” by an empty patch (gold_validation); if any system's run resolved it with an empty patch it is a free point — check on the cluster.
